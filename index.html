A real-time physics engine for robotics simulation.

A.P.E. (Asimov Physics Engine) is a C++-based real-time physics and simulation engine named after Isaac Asimov. It combines an Entity Component System, real-time rendering, rigid-body physics, and an integrated editor — built to work alongside ROS (Robot Operating System).

Overview

Bridging game-engine simulation and robotics development

The project aims to bridge the gap between game-engine-style real-time simulation and robotics development.

By combining physics simulation with ROS, A.P.E. provides an environment for experimenting with robotic systems, sensors, rigid-body dynamics, collision detection, and simulated environments — before deploying them to physical hardware.

Modularity is a core design principle: individual systems such as the renderer, physics engine, ECS, and ROS integration can evolve independently while communicating through a common engine architecture.

Long-term vision

A lightweight, extensible simulation platform for:

  • Robotics simulation
  • Physics experimentation
  • ROS-based development
  • Autonomous systems
  • Sensor simulation
  • Robot visualization
  • Real-time environment prototyping
  • Game and simulation development
Architecture

Engine subsystems

A.P.E. is divided into several major subsystems, each responsible for a specific part of the runtime and editor. They communicate through shared scene and entity data, keeping the engine extensible.

User Interface

Built with Dear ImGui (docking branch) for a flexible, rearrangeable editor workflow — inspecting scene hierarchy, editing components, and interacting with files.

Entity Component System

Powered by EnTT. Separates entities from the data associated with them, keeping engine systems decoupled and modular. Components represent transforms, rendering, or physics properties.

Renderer

Currently OpenGL with GLFW for window/input and GLAD for function loading. A Vulkan backend via Rust is planned for a lower-level alternative.

Physics

Simulation via ReactPhysics3D. Provides collision detection and rigid-body simulation, plus an editor collider-selection interface for configuring collision geometry.

The editor sits on top of these systems, providing an interactive interface for inspecting and modifying the current engine state. Rendering systems consume rendering components; the physics system operates on entities with physical properties — all sharing the same ECS data model.

Editor Features

An editor-driven workflow

A.P.E. ships with an integrated editor designed to make scene construction and physics experimentation interactive — no code changes required.

Scene Outliner

A hierarchical view of all objects currently present in a scene. Quickly inspect the scene and select individual entities for further editing — the central navigation point for managing objects in the editor.

Properties Editor

Inspect and modify the components attached to a selected entity. Rather than requiring property changes directly in code, the editor exposes relevant component data through the UI — making scene construction and experimentation interactive.

Add Object

Create new entities directly from the editor. A straightforward workflow for constructing scenes and testing combinations of rendering and physics components — without manually creating every object in code.

Delete Object

Remove entities directly from the scene. Complements the scene-management workflow — quickly create, test, and remove objects while iterating on a scene.

File Dialog

An integrated file dialog for interacting with files and engine resources. The foundation for managing external assets and scene-related files from within the editor — no need to switch to external file-management tools.

Collider Selector

Choose the type of physics collider associated with an object. Configure collision geometry directly within the editor for a more visual workflow when setting up physical interactions between objects.

Project Goals

Roadmap

The long-term goal is a flexible real-time engine with a strong editor-driven workflow. Current development focuses on building core systems and establishing a modular architecture that can support additional rendering, physics, asset-management, and editor functionality in the future.

◈ Rust-based rendering components
◈ Improved scene and asset management
◈ Expanded physics functionality
◈ Additional editor tools
◈ Scene serialization
